Project Title: Mobile-Based Semantic Lost and Found Recovery Platform
CHAPTER 1: INTRODUCTION
1.1 Introduction
This project develops and evaluates a Mobile-Based Semantic Lost and Found Recovery Platform which is a mobile application platform that uses Natural Language Processing (NLP) to improve the accuracy of matching lost and found items and making retrieval of lost items more efficient. This chapter sets the context, defines the problem, define the aim of the project, outlines objectives, describes the methodology and covers the project’s significance, feasibility and ethical considerations.
1.2 Background and Context of the Project
Traditional lost and found systems rely on physical logs or simple digital databases that use keyword-based searches. Although digitization improved record accessibility, these systems still struggle to interpret the semantic meaning of textual descriptions, leading to low recovery rates, inefficiency and user frustration.
Recent advancements in Natural Language Processing (NLP), specifically in semantic text matching enable systems to compare textual descriptions based on context and meaning rather than exact keywords. These developments present an opportunity to transform lost and found services into intelligent, text-based retrieval systems that improve matching accuracy and efficiency. The main challenge is to apply these technologies effectively to achieve both accuracy and practicality in real world recovery scenarios.
1.3 Problem Statement
The existing lost and found item retrieval systems exhibit low matching accuracy because they rely on lexical cosine similarity algorithms that compare keywords rather than understanding meaning. This lexical dependence prevents the system from bridging the semantic gap between textual item descriptions (e.g., “navy blue Herschel backpack with leather straps”) and visual data (e.g., an image of a “dark blue backpack with leather handles”). Consequently, these systems achieve poor retrieval performance, require extensive manual verification and delay item recovery. The goal of this project is to develop and evaluate an NLP-based semantic text matching system that aligns textual descriptions to improve retrieval accuracy and efficiency by at least 30% in Mean Reciprocal Rank (MRR)
1.4 Aim
To design, develop and evaluate a Mobile-Based Semantic Lost and Found Recovery Platform that significantly improves the accuracy, efficiency and security of lost and found item recovery.
1.5 Research Objectives
To design and implement an NLP based semantic matching algorithm that generates embeddings for text and metadata (time and location) features, achieving at least 30% improvement in Mean Reciprocal Rank (MRR) compared to a baseline keyword-based system.
To develop a proactive searching mechanism that continuously monitors the system’s database for new matches to lost items ensuring users are automatically notified when a potential match is found even if the found item is reported days or weeks later.
To integrate and test a multi layered verification workflow that incorporates a secure “secret question” mechanism, aiming to reduce false claim rates by 25% and achieve a user verification success rate above 90% during controlled evaluations.

The scope and limitations of this project are outlined below to clearly define the system’s boundaries, highlight the key functionalities addressed and acknowledge constraints encountered during development.

Design, development, and evaluation of a functional mobile application prototype of the Mobile-Based Semantic Lost and Found Recovery Platform.
Its core functionalities include:

Automated semantic matching using Natural Language Processing models.
Proactive searching of lost items in the vector database

Testing and evaluation using standard information retrieval metrics.

Scalability designed but actual deployment and stress-testing limited by computational resources and time.

Basic security measures included but no comprehensive penetration testing or security audits.
Focus on common lost and found items (bags, phones, wallets, keys) and not optimized for specialized or unusual items.
Limitations will be addressed in future work and recommendations for system enhancement.

2.2 Review of Relevant Literature
The following sections review key literature sources that provide foundational insights into the development of semantic text matching systems for lost and found items. These sources are organized to reflect the progression from traditional keyword-based systems to advanced NLP-driven approaches, as well as the integration of proactive searching and verification layers to enhance security.
Traditional Digital Lost and Found Systems
Shrivastava et al. (2025) developed a traditional digital lost and found platform that relies on keyword-based matching and manual user searches. The system uses a React.js frontend and MongoDB backend to digitize the process of reporting and retrieving lost items. While this approach improves accessibility compared to physical logbooks, it suffers from significant limitations. The system’s reliance on lexical matching means it cannot interpret the semantic meaning behind varied descriptions of the same item. For example, a user searching for a "navy blue backpack" would not retrieve results for a "dark blue bag," even if both descriptions refer to the same item. This lack of semantic understanding leads to low retrieval accuracy, user frustration and inefficiency in the matching process.
The proposed system addresses these limitations by replacing keyword-based matching with semantic text matching using SBERT embeddings. This approach automates the retrieval process, ensuring that items are matched based on their contextual meaning rather than exact keyword alignment, thereby improving both accuracy and user experience.
Sentence-BERT (SBERT) for Semantic Embeddings
Muennighoff (2022) introduced Sentence-BERT (SBERT), a transformer-based model designed to generate semantically meaningful embeddings for sentences and short texts. SBERT outperforms traditional models like TF-IDF and Word2Vec by capturing the contextual relationships between words, making it ideal for tasks that require nuanced understanding, such as matching textual descriptions in lost and found systems. For instance, SBERT can effectively link descriptions like "navy blue Herschel backpack with leather straps" and "dark blue Herschel brand bag featuring leather handles" by recognizing their semantic equivalence.
However, SBERT is computationally intensive and requires fine-tuning for domain-specific applications. The proposed system addresses this by implementing a lightweight, fine-tuned version of SBERT optimized specifically for lost and found item descriptions. This ensures that the model remains efficient and scalable while maintaining high accuracy in semantic matching.
gMatch: Semantic Matching for Knowledge Base Question Answering
Jiao et al. (2021) developed gMatch, a semantic matching-based approach for knowledge base question answering (KBQA). gMatch uses Siamese neural networks to compute the semantic similarity between natural language questions and SPARQL queries, ensuring that the generated queries accurately reflect the user’s intent. This system is particularly effective in reducing semantic loss between questions and queries, which is a common issue in traditional KBQA systems that are often decoupled from the knowledge base.
While gMatch is designed for structured knowledge bases, the proposed system adapts its Siamese network architecture to focus on unstructured textual descriptions of lost and found items. By eliminating the dependency on knowledge bases, the system becomes more flexible and scalable, capable of handling the varied and unstructured nature of real-world lost and found reports.
HA-RCNN: Short Text Similarity with Attention Mechanisms
Ji and Zhang (2022) proposed HA-RCNN, a model that combines BiGRU, CNN and a headword attention mechanism to calculate short text similarity. This approach enhances the influence of key words such as nouns and verbs that carry the most meaningful information in a sentence. For example, in the sentence "Lost my brown wallet near the library," the words "brown," "wallet," and "library" are prioritized to improve the accuracy of similarity calculations.
HA-RCNN achieves higher recall and F1 scores compared to traditional methods, but its complexity and the need for large datasets can limit performance in smaller-scale applications. The proposed system simplifies this approach by focusing the attention mechanism specifically on key item descriptors, such as color, brand, and location. This ensures that the most relevant features are prioritized during matching, improving both efficiency and accuracy.
Semantic Question Answering Systems
Antoniou and Bassiliades (2021) provided a comprehensive survey of semantic question answering (SQA) systems, which convert natural language questions into structured queries (e.g., SPARQL) to retrieve answers from knowledge bases. These systems employ a variety of techniques, including dependency parsing, entity and relation extraction and semantic graph-based models to represent questions and their corresponding answers.
However, SQA systems typically require structured knowledge bases, which limits their scalability for unstructured data, such as the textual descriptions found in lost and found reports. The proposed system eliminates this dependency by focusing on unstructured textual descriptions, making it more adaptable to real-world scenarios where items are described in varied and informal ways.
TextSLAM: Visual SLAM with Semantic Text Features
Li et al. (2022) introduced TextSLAM, a visual SLAM system that integrates semantic text features to improve localization and mapping in dynamic environments. TextSLAM treats text as planar patches with semantic meaning, allowing it to match text objects across varying conditions, such as day and night or different viewpoints. The system uses Levenshtein distance to measure the similarity between text strings, ensuring that semantic meaning remains invariant even when visual appearances change.
While TextSLAM is designed for visual SLAM and not directly applicable to lost and found item retrieval, it demonstrates the robustness of semantic text matching in dynamic environments. The proposed system adopts a text-only approach, optimizing the matching process for mobile accessibility and eliminating the need for visual data, which can be both impractical and a security risk in lost and found scenarios.
Campus Lost and Found Audit: Fraud and Verification
Honde and Mutasa (2024) conducted an audit of campus lost and found systems, revealing a 60% fraudulent claim rate due to the absence of verification mechanisms. The study highlights that systems relying solely on textual descriptions or images are vulnerable to exploitation, as individuals can easily guess common item descriptions (e.g., "Black iPhone") to fraudulently claim items.
The proposed system addresses this critical gap by implementing a multi-layered verification workflow. This includes secret questions (e.g., "What’s inside the wallet?") and admin oversight to review flagged claims, significantly reducing the risk of fraud and enhancing user trust in the system.
Hybrid Lost and Found Systems
Prawira and Saputri (2023) developed a hybrid lost and found system that combines TF-IDF for text and ResNet-50 for image matching. While this approach represents an advancement over purely keyword-based systems, it suffers from poor image matching accuracy (less than 30%) and static thresholds that limit adaptability to real-world variations in item descriptions and image quality.
The proposed system eliminates the dependency on images entirely, focusing instead on semantic text matching with dynamic thresholds. This not only simplifies the architecture but also enhances scalability and security by removing the risks associated with image uploads, such as fraud or privacy concerns.
Multi-Modal Systems for Lost and Found Items
Dhanawardhana et al. (2025) proposed a multi-modal system that uses a dual-tower vision-language model to fuse images, text, and metadata for lost and found item retrieval. While this approach achieves high accuracy by leveraging multiple data types, its complex architecture and reliance on multi-modal data make it less practical for widespread deployment, particularly in resource-constrained environments.
The proposed system simplifies this process by focusing on text-only matching, which is not only more scalable but also more secure and accessible. By eliminating the need for image processing, the system reduces computational overhead and mitigates the risks of fraud and privacy breaches associated with image uploads.

2.4 Identification of Gaps or Areas for Improvement
This section analyzes the existing literature to identify gaps, unanswered questions and limitations in current lost and found systems. These gaps highlight the need for the proposed system and underscore its potential to make unique contributions to the field.
Inefficient Matching Mechanisms
One of the most significant limitations of current lost and found systems is their reliance on lexical or keyword-based matching. This approach leads to poor retrieval accuracy, particularly when item descriptions vary even slightly. For example, a system using TF-IDF might fail to match a "navy blue backpack" with a "dark blue bag," resulting in missed connections and user frustration.
The proposed system addresses this gap by adopting semantic embeddings generated by SBERT, which capture the contextual meaning of textual descriptions. This ensures that items are matched based on their semantic similarity rather than exact keyword alignment, significantly improving retrieval accuracy and user satisfaction.
Limited Semantic Understanding
Current systems often lack deep semantic comprehension, failing to interpret the nuanced details or varied descriptions of the same item. For instance, a system using ResNet-50 for images and TF-IDF for text may not recognize that "wallet" and "billfold" refer to the same object, leading to low match quality and high false negatives.
The proposed system leverages transformer-based models like SBERT to achieve a deeper understanding of textual descriptions. This allows the system to recognize synonyms, paraphrases, and other linguistic variations, ensuring that items are matched accurately regardless of how they are described.
Lack of Proactive Matching Mechanisms
Existing lost and found systems typically only attempt to match lost items with found items at the time of reporting. Once a lost item is registered, there is no automated process to continuously check for new matches as additional found items are reported. This results in missed recovery opportunities, particularly when found items are reported days or weeks after the lost item. This gap forces users to manually revisit the system to check for updates, which is both time-consuming and frustrating. Some systems, such as those described by Shrivastava et al. (2025), rely entirely on user-initiated searches, placing the burden on the user to remember to check for new matches.
The proposed system addresses this gap by introducing a proactive searching mechanism that automatically re-scans the database for new matches to lost items over a configurable period (e.g., 30 days). By reducing the need for manual follow-ups, this feature improves user satisfaction, recovery rates, and trust in the system.
Verification and Security
A critical gap in existing lost and found systems is the absence of robust verification mechanisms. Without verification, these systems are vulnerable to fraudulent claims, where individuals can exploit weak matching algorithms to claim items that do not belong to them. Honde and Mutasa (2024) found that up to 60% of claims in campus systems were fraudulent due to this lack of oversight.
The proposed system introduces a multi-layered verification workflow, including secret questions and admin oversight, to address this issue. This ensures that only legitimate claims are approved, significantly reducing fraud and enhancing user trust in the system.
Adaptability and Learning Deficiencies
Most existing systems use static models and thresholds that do not improve with user feedback or adapt to new data. This limits their long-term performance and domain-specific optimization, as the systems cannot learn from failure cases or evolving user needs.
The proposed system incorporates continuous learning, allowing the model to refine its matching algorithms based on user feedback and successful/failed matches. This ensures that the system remains adaptive and scalable, improving its accuracy and efficiency over time.
Accessibility and Mobile Optimization
Traditional lost and found systems are often web-based and not optimized for mobile accessibility. This limits their reach and usability, particularly in scenarios where users need to report or search for lost items on the go.
The proposed system is designed as a mobile app using React Native, ensuring cross-platform accessibility and a seamless user experience. This makes the system more user-friendly and practical for real-world deployment.
Security and Privacy Risks
Systems that rely on image uploads for matching introduce significant security and privacy risks. Fraudsters can exploit image data to make fraudulent claims, while users may be hesitant to upload images of personal items due to privacy concerns.
The proposed system eliminates these risks by focusing on text-only matching, removing the need for image uploads entirely. This not only enhances security but also simplifies the system architecture, making it more scalable and efficient.

3.3.1 Data Handling and Feature Engineering
The system’s NLP-based semantic matching relies on careful data handling and feature engineering, which includes data acquisition, preparation and utilization for training and evaluation. The following subsections outline the processes involved:
Data Collection
The system uses public text datasets to train and evaluate the semantic matching model. These datasets include:
Common Crawl: A large-scale repository of web-crawled text data, providing diverse and realistic textual descriptions.
Wikipedia and Domain-Specific Corpora: Used to augment the dataset with descriptions relevant to common lost and found items (e.g., bags, phones, wallets, keys).
Synthetic Data: Additional paraphrased examples are generated to simulate writing variations (e.g., “blue HP laptop bag” → “navy laptop backpack from HP”). This increases robustness to natural linguistic diversity
This multi-source dataset ensures both generality and domain relevance.
Data Cleaning and Transformation
Before modelling, the dataset undergoes standardized preprocessing to improve text quality and ensure consistent representation.
Noise Removal: Eliminates incomplete, irrelevant or extremely short descriptions.
Standardization: Uniform formatting is applied, including removal of special characters when unnecessary.
Tokenization: Performed using the Hugging Face tokenizer associated with Sentence-BERT. This ensures compatibility with the model’s vocabulary and token segmentation rules.
Normalization: Descriptions are lowercased; excessive whitespace and irrelevant symbols are removed.
Paraphrase-Based Augmentation: Additional linguistic variations are introduced through rule-based or model-assisted paraphrasing to improve model robustness.
Unlike traditional NLP pipelines, lemmatization and stemming are not used, as transformer-based models such as SBERT rely on contextual rather than surface-level token features.
Feature Selection and Engineering
The system’s semantic matching relies on feature engineering to convert textual descriptions and contextual metadata into numerical representations that support semantic similarity computation.
1. Semantic Text Embeddings (Primary Feature)
The main feature representation uses Sentence-BERT (SBERT) to generate high-dimensional, context-aware sentence embeddings.
SBERT transforms each description into a 768-dimensional (or 512 depending on model variant) embedding.
These embeddings capture semantic meaning, enabling the system to identify matches even when descriptions differ lexically (e.g., “Samsung phone with cracked screen” vs. “broken Samsung smartphone”).
SBERT is chosen for its proven performance in semantic similarity tasks and its efficiency when used with vector search systems (FAISS).
2. Metadata Engineering (Contextual Features)
To improve matching accuracy, additional non-textual features are encoded:
Location Encoding: Locations such as “Library”, “Cafe”, or “Engineering Building” are mapped to numerical vectors using one-hot or embedding mappings.
Time Encoding: Time metadata (e.g., “14:00”, “Morning”, “Weekday”) is converted into temporal buckets or cyclic encodings.This captures temporal proximity, helping the system prioritize items lost around the same time and location.
3. Feature Fusion
For ranking matched pairs, the system combines:
Cosine similarity of SBERT embeddings
Location proximity score
Temporal proximity score
A weighted scoring function is then used to re-rank candidates, improving practical matching performance beyond pure text similarity.
Dataset Considerations
The dataset is designed to be diverse, realistic, and balanced:
Diverse Descriptions: Includes varied and informal descriptions to reflect real-world usage.
Balanced Categories: Ensures representation across common lost and found items (e.g., bags, phones, wallets, keys) to avoid bias.
Ethical Compliance: Data collection and usage adhere to ethical guidelines, including user consent and anonymization where applicable.
3.3.2 NLP Model Development and Training
The core of the system is an NLP-based semantic matching model designed to align textual descriptions of lost and found items. The following subsections detail the model’s architecture, training and validation.
Model Selection and Architecture
The system employs Sentence-BERT (SBERT) as the primary model for generating semantic embeddings from textual descriptions. SBERT is chosen for its ability to:
Capture contextual meaning and semantic relationships between words.
Handle synonyms, paraphrases, and varied descriptions effectively.
Outperform traditional models like TF-IDF and Word2Vec in semantic understanding tasks.
The model architecture includes:
SBERT Encoder: Converts textual descriptions into 512-dimensional embeddings that represent their semantic meaning.
Similarity Module: Computes cosine similarity between embeddings to identify potential matches.
Metadata Fusion: Incorporates location and time features to re-rank matches based on spatial and temporal proximity.
Hybrid Ranking Algorithm: A custom algorithm was engineered to combine the NLP score with metadata constraints. The final relevance score (S final ) is calculated as:
S final = ( W1  * S semantic) + ( W2  * S time) + ( W3  * S location)
Where:
S semantic is the Cosine Similarity score between the text vectors (ranging from -1 to 1)
S time is a decay function that prioritizes items found closer to the reported loss date.
S location is a binary or radius-based score matching the lost and found locations.
W represents tunable weights determined during the testing phase.
Training and Validation
The model is trained and validated using the following process:
Data Splits: The dataset is divided into 70% training, 15% validation, and 15% test sets to ensure robust evaluation.
Loss Function: Contrastive loss is used to maximize similarity for matching pairs and minimize it for non-matching pairs.
Hyperparameters: 
Optimizer: AdamW with a learning rate of 2e-5.
Batch Size: 32.
Epochs: 10 (with early stopping if validation performance plateaus).
Evaluation Metrics: 
Mean Reciprocal Rank (MRR): Measures the ranking quality of correct matches.
Recall@K: Percentage of correct matches in the top-K results.
Precision@K: Accuracy of the top-K matches.
Proactive Searching for Unmatched Lost Items
One of the key innovations of the system is its proactive searching mechanism, which continuously searches for matches for lost items that have not yet been found. This feature ensures that users are notified as soon as a matching found item is reported, even if the match does not occur immediately after the lost item is registered.
How Proactive Searching Works:
Vector Database Indexing:
When a user reports a lost item, the system generates its semantic embedding using SBERT and stores it in a vector database (FAISS).
The embedding is indexed for fast similarity search, allowing the system to efficiently compare it against newly reported found items.
Periodic Matching Checks:
The system periodically re-scans the vector database (e.g., every 24 hours) to check for new matches.
This ensures that even if a found item is reported days or weeks later, the system will automatically detect and notify the user of the potential match.
Feasible Search Period:
Proactive searching is applied for a feasible period (e.g., 30 days), after which the lost item report is archived but remains searchable.
Users receive notifications if a match is found within this period, reducing the need for manual follow-ups.
Efficiency Considerations:
The vector database is optimized for low-latency searches, ensuring that proactive matching does not degrade system performance.
Batch processing is used to minimize computational overhead during periodic scans.
Bias and Ethical Considerations
The model is designed with bias mitigation and ethical compliance in mind:
Dataset Bias: The dataset is augmented to include diverse descriptions and mitigate bias.
Privacy: Data collection is minimized, and users can request data deletion.
Security: Role-based access control and encryption are implemented to protect user data.
Transparency: The system provides explanations for matches (e.g., “Matched based on description and location”).
Verification Workflow
A secure verification workflow ensures that items are returned to their rightful owners. The workflow includes:
Secret Question Mechanism: Lost and Found Office staff set a secret question (e.g., “What’s inside the wallet?”) when uploading found items. Losers must answer correctly to claim an item, providing a simple yet effective verification layer.
Admin Oversight: Admins review flagged claims (e.g., incorrect answers) and request additional proof (e.g., receipts, photos) if needed.
This multi-layered approach balances security with usability, preventing both false positives and unnecessarily burdensome verification for legitimate claimants.
